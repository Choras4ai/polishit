# Runshi 1.7.0 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans; complete tests before implementation, followed by independent whole-change review.

**Goal:** Reliable source review, protected terminology and explicit risk checks, and ID-bound explanations in version 1.7.0.

**Architecture:** Reuse SourceReview and verified source-edit sessions. One pure review safety helper is shared by pipeline metadata and main-process write authorization. Explain existing diff IDs in bounded batches; no new model provider or live typing subsystem.

**Tech Stack:** Existing Electron/Node, native macOS accessibility, JavaScript node:test.

**Spec:** docs/grammarly-benchmark-2026-10-22.md

## Global Constraints
- No dependency additions; no unverified source writes.
- Protected terms block acceptance; numerical/claim changes require explicit per-change confirmation.
- Apply the same safety rules to inline, result, batch, whole-text and copy paths.
- Separate automated checks from actual Word acceptance; Windows requires its own runtime.

## Review Focus
- Repeated terms and UTF-16 ranges with emoji; preserve all occurrences.
- Renderer-forged IDs or safety flags cannot bypass main validation.
- Numbers swapped without changing the multiset must still trigger review.
- Duplicate phrases get the correct reason by ID and exact content.
- Missing geometry/changed document yields persistent status and no stale write.
